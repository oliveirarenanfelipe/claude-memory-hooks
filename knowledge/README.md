# The knowledge

This is the third part of the project, and it is being written in blocks.

## What goes here

Lessons that survive the project they were learned in. Not advice — findings. The
difference is that a finding names what was measured, what was believed before,
and what changed.

They are plain notes with frontmatter, so the engine indexes them like any other
memory: once installed, they come back on their own when the subject comes up in
a conversation, in any project. That is the point of shipping them as notes
rather than as a document — a document has to be remembered and opened; a note
arrives by itself.

## Why it is empty right now

The source material is a working set of a few hundred cross-cutting notes, and
86% of them cite a real client, a real system or a real person by name. That is
not decoration: the specific case is what makes a lesson land. *"Don't trust a
green test"* is a slogan; *"the check ran forty-eight times in green while the
source it read had been empty for a month"* teaches something.

So this is not a copy job. Each note has to be rewritten with an equivalent
invented case that carries the same shape, and each rewrite is a judgement about
what survives. That work is being done in blocks and reviewed one note at a time,
rather than dumped in one pass — because a bad decision applied three hundred
times is three hundred bad notes.

## The honest limitation, stated up front

Because the cases here are reconstructed rather than reported, **the numbers in
this folder are illustrative, not measured.** Where a claim depends on a real
measurement, the note says what was measured and how, without the identifying
context. Where the story is a stand-in, it says so.

That is a deliberate trade: the alternative was publishing other people's
operational detail, which is not ours to publish.

## What is already here

Nothing yet. The first block lands with the engine and the method already in
place, so that a lesson arriving in your context has something to act on.

If you want to see the shape they will take, the fixture corpus in
`engine/tests/fixtures/` contains a few synthetic notes written in exactly this
format — including one marked `scope: global`, which is the flag that makes a
note travel across projects.
