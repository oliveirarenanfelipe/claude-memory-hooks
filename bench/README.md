# bench: does your rules file actually change anything?

Everyone ships a `CLAUDE.md` with coding rules. Almost nobody measures whether it
changes what the model does. This folder measures it.

`bench.py` runs the same coding requests through Claude Code with different rules
files, in isolation, and has a blind judge count the mistakes. You can drop your own
rules file into `rules/` and see where you stand.

## What we found (25/09/2026)

22 requests, each with a trap a careless assistant falls into: a drive-by refactor
next to a real bug, a user diagnosis that the code contradicts, a "pure refactor"
where the idiomatic shortcut changes behavior, a request that would log a password,
a test that is easier to weaken than to fix, a slow endpoint with no measurement.
Three arms, two runs each, one blind judge per case.

| rules | mistakes (22 cases x 2 runs) | on the 10 cases no rules author saw |
|---|---|---|
| none (the bare model) | 17 | 5 |
| [andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills) `CLAUDE.md` | 10 | 3 |
| [`rules/house.md`](rules/house.md) (this repo) | 0 | 0 |

**Read this before quoting those numbers:**

- **The bare model is already good.** In 13 of the 22 cases no arm made a single
  mistake, the bare model included. Rules files matter less than their popularity
  suggests. The differences live in a handful of situations: measuring before
  optimizing, not trusting the user's diagnosis, and staying inside the request.
- **12 of the 22 cases were written by the author of `house.md`,** and one paragraph
  of it ("scope is the request") was added after seeing them. The other 10 were
  generated by an isolated model that never saw any rules file
  (`cases.json`, ids H13 to H22). Judge the result on those 10 first.
- **One model, one judge per case, two runs per arm.** The judge is the same model
  family as the answerer. A one- or two-point gap between arms is within the noise we
  measured when repeating the same arm.
- **This measures single replies to written requests,** not long agentic sessions.

## How it isolates the arms

Every reply is a separate `claude -p --restricted --strict-mcp-config --tools ""`
started from an empty folder. Restricted mode ignores user, project and local
settings, so no `CLAUDE.md`, no hooks and no memory leak in. We checked that by
asking the isolated model to list every instruction it received beyond the default
prompt: it reported none. The rules under test enter through
`--append-system-prompt-file`.

## Run it

Requires Claude Code logged in, and Python 3.8+. It spends real usage: about
130 replies and 22 judge calls for the full set.

```bash
cd bench
# the third-party rules are downloaded, not redistributed here
curl -o rules/karpathy.md https://raw.githubusercontent.com/multica-ai/andrej-karpathy-skills/main/CLAUDE.md
python bench.py answer     # replies, resumable
python bench.py judge      # one blind judge per case
python bench.py score      # the table
```

To test your own rules, save them as `rules/mine.md` and run with
`--arms none,mine,house --run runs/mine`. The replies and verdicts from our run are in
`runs/default/`, so you can read every answer and every judgment behind the table.

## Add a case

A case is an object in `cases.json`: `request` and `code` (what the model sees),
`note` and `rubric` (only the judge sees them). A good case has a trap you can verify
by reading the code, and rubric lines a judge can check in the reply text. Run the
code behind any claim in the note before trusting the case.
