# claude-memory-hooks

> Claude Code remembers everything. No server. No database. No cost.

[Leia em Português](README.pt-br.md)

---

## The problem

If you use Claude Code seriously, you've hit these walls:

1. **Claude forgets everything between sessions** — you explain the same context over and over
2. **Multiple projects, no continuity** — switching projects means starting from scratch
3. **Work disappears when you don't save** — close the session and the reasoning behind decisions is gone

---

## What this does

Three lightweight hooks that run silently inside Claude Code:

| Hook | When | What it does |
|---|---|---|
| `session_context.py` | Session opens | Injects your last session brief into Claude's context |
| `prompt_memory.py` | You type a prompt | Detects the topic and injects relevant memory |
| `auto_brief.py` | Session closes | Reads the conversation and saves a brief automatically |

**No LLM calls. No API key needed. No external services. Just Python and Markdown files.**

Memory is stored as plain `.md` files you can read, edit, or delete anytime.

---

## How it feels

**Before:**
> You: "So continuing from yesterday, we were working on the payment integration where the webhook was—"
> Claude: "I don't have context from previous sessions..."

**After:**
> *(Session opens)*
> Claude already knows: project name, last task, next step, active blockers.
> You just... continue.

## Install

**Requirements:** Python 3.8+, Claude Code

```bash
git clone https://github.com/oliveirarenanfelipe/claude-memory-hooks
cd claude-memory-hooks
bash install.sh
```

Then open Claude Code and run:

```
/memory-setup
```

Claude will ask you a few questions about your projects and configure everything.

---

## Setup experience

`/memory-setup` is a guided conversation — no config files to edit manually:

```
Claude: How many projects do you work on with Claude Code?
You: Three — my SaaS product, a client website, and my content project

Claude: Where does your SaaS product live on your computer?
You: /Users/me/Projects/my-saas

Claude: What words would you typically type when talking about it?
You: dashboard, billing, users, stripe

[repeats for each project]

Claude: All set. From now on I'll remember where you left off.
```

---

## What gets saved

At the end of each session, a brief is automatically created at:

```
~/.claude/projects/<your-project>/memory/session_briefs/<project>.md
```

```markdown
**Date:** 2025-01-15
**Project:** my-saas

**What was done:** Implemented Stripe webhook handler for subscription cancellations.
**Files touched:** `webhooks/stripe.py`, `models/subscription.py`
**Next step:** Test the cancellation flow end-to-end with Stripe CLI
**Blocker:** None.
```

Human-readable. Editable. Yours.

## Touch points

The system runs silently but lets you know it's working:

- `📝 Brief saved — project-name` — appears when a session brief is saved
- Context is injected automatically at session start (you'll notice Claude already knows things)

## Project structure

```
~/.claude/
  hooks/
    auto_brief.py       — Stop hook (120s timeout)
    session_context.py  — SessionStart hook (10s timeout)
    prompt_memory.py    — UserPromptSubmit hook (5s timeout)
  memory-hooks/
    config.json         — your projects and keywords (generated by /memory-setup)
  commands/
    memory-setup.md     — the setup skill
```

## Philosophy

This was built by studying [claude-mem](https://github.com/thedotmack/claude-mem) — a popular memory system with 58k stars.

The difference: claude-mem runs a persistent local server, uses SQLite, ChromaDB for semantic search, and has a complex worker architecture. It's powerful.

This project does the same core thing with three Python scripts and Markdown files. Nothing to keep running. Nothing to break.

The key insight: Claude Code hooks can return `hookSpecificOutput.additionalContext` — any text you put there gets injected into Claude's context. That's the whole mechanism.
